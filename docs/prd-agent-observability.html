PRD — closing the see-and-verify loop for cloud agents

The agents aren't dumber than you. They're blind.

Every soak failure on record falls into two classes a headless agent structurally cannot verify: how the UI looks and what the real game's data actually is. Local sessions win because the human closes the observe→act loop in seconds; the cloud loop closes it once per alpha, through the maintainer's hands. This PRD gives the agents their own loop closure — eyes for the UI, replayable reality for the data — and moves the human's visual check to the cheapest possible point.

01

Problem — the evidence, not the vibe

Verified against the full soak history (2026-07-11 → 2026-07-14). Both agents run Opus 4.8; the issues are well-specified. Model and issue quality are eliminated as causes — observability is what remains.

Failure class A — visual / layout (~5 of 9)

Things only an eye catches:

  • {s.rotmg} literal rendered in the DPS summary (#89)
  • Clipped / hidden pinned rows, jittering panel heights (#91, #93)
  • Bad contrast, wrong color coding (#113)
  • Sprite outline several pixels too thick (#147)

Failure class B — real-game data contracts (~4 of 9)

Things only live traffic / real assets reveal:

  • Loot bags never recognized on real assets (#113, #144)
  • Equip/unequip counted as a drop (#122)
  • Realm boss damage misattributed (#98)
  • Other players' damage missing (#50)

The canonical failure: the loot saga

Issue #105 (well-written, clear acceptance criteria) → PR #106 → soak fails #113, #122, #136, #144 → finally fixed in PR #146. The agent assumed bag entities self-report Class=Bag+BagType; on real assets that scan finds nothing. Its fake test data (IdToAsset.registerFake) was generated from the same assumption under test — circular validation. Four install-and-play round-trips for what one line of real data would have prevented.

The capture promise is aspirational

The bug form calls the repro capture "the linchpin," but the overlay has no test runner at all, nothing consumes a realmshark-bug-*.json, and the one Java test written from a capture was hand-transcribed by eye. Worse: #144's capture couldn't contain the evidence — the capture allowlist dropped the lootBagTypes envelope (fixed only as a side effect of PR #146).

02

Goals & non-goals

Goals

  • G1 — the agent sees its UI before the PR opens (headless render + screenshot + look).
  • G2 — the maintainer sees screenshots before installing anything (soak-issue gallery).
  • G3 — every live-game bug becomes a permanent replay test (TS now, Java phase 2).
  • G4 — agents work from real game data, not self-fulfilling fakes (capture corpus + asset facts).

Non-goals

  • No pixel-golden CI gating — humans and the multimodal reviewer judge images, not byte-diffs.
  • No blocking human signoff by default — hands-off stays; signoff is opt-in per issue.
  • No committed raw game assets — distilled facts and filtered captures only.
  • No live-game automation — the soak stays; the goal is first soaks that pass.
  • No .github/ changes by agents — the guardrail and review tripwire stand.

Success metrics (baseline → target): soak first-pass rate 2/8 → most waves; installs per shipped wave up to 6–8 → 1–2; every soak:fail with a capture yields a committed replay fixture in its fix PR.

Locked decisions (ground truths)

Settled in design discussion 2026-07-14. These are the positions the features below implement.

#DecisionWhy
D1Three-eyes screenshot model, non-blocking by default. Build agent must look → review agent (multimodal) scores images → maintainer reviews a before/after gallery in the soak issue. Opt-in ui:signoff label makes it blocking per issue.Exhaust the cheap eyes before spending the human's. The soak issue is the already-designed human touchpoint — no new interruption. Blocking-by-default would human-gate the most common PR type.
D2Capture ring ~10k envelopes, per-type quotas, compact JSON, gzipped.Agent read cost is irrelevant (programmatic). Real constraints: GitHub's 25 MB attachment limit (gzip solves) and spam-type eviction — MovePacket/NewTickPacket dominate a count-based ring; quotas stretch wall-clock coverage.
D3Replay determinism via vitest fake timers + timestamp anchoring. No production clock refactor.DpsTracker.ts:609, useDpsTracker, LootTracker.ts:254 compare envelope time against Date.now(); last week's capture reads as "everything expired." vi.setSystemTime anchored to the capture's own timeline fixes it test-side.
D4TS replay first; Java replay mirror is phase 2 but required.Attribution is computed bridge-side (DpsBroadcaster runs DpsEngine, emits precomputed type:"dps" envelopes; TS only displays them). #50/#98-class bugs are Java bugs — TS replay of dps envelopes reproduces the display of wrong data, not the bug.
D5Corpus grows organically; seed once. Per-issue capture attachment is the primary habit; used captures are committed as fixtures by the agent's PR. One maintainer-recorded "kitchen-sink" session seeds the corpus. A session-record toggle makes recording free.Pre-building a scenario matrix guesses at future needs; organic growth is targeted and self-maintaining.
D6Asset facts = distilled JSON of only the consumed fields, extracted by the maintainer per game update. Feeds headless tests and seeds registerFake.Real asset semantics (bag entity classes, BagTypes, enchant strings) are exactly what agents keep guessing wrong. Facts-only data is small and defensible.
D7Screenshots live at stable per-panel paths, overwritten in place (docs/screenshots/panels/<type>-<size>.png).Stable paths make before/after trivial (same path at bridge vs staging refs), bound repo growth, and let the PR body, reviewer, and soak issue reference the same artifacts.
04

Feature 1 — Renderer harness & screenshots ("eyes")

The renderer is plain React + Tailwind; its only Electron dependency is the window.overlay API (~25 methods in overlay/src/preload/index.ts). Anything that provides window.overlay can host the renderer in ordinary headless Chromium — window attachment is irrelevant to "does the panel render correctly."

overlay/
  src/renderer/src/harness/
    shim.ts            # implements OverlayApi without Electron
    wsSource.ts        # live-fake mode: WS straight to the --fake bridge (mirrors bridgeClient.ts)
    fixtureSource.ts   # fixture mode: load + play a capture/fixture JSON
  vite.harness.config.ts   # plain vite (npm run dev is electron-vite — spawns Electron; harness must not)
  e2e/
    shots.spec.ts      # Playwright: mount each panel x size, screenshot
  test/fixtures/
    gallery.json       # standard fixture that populates every panel — comparable shots
    spritePack.json    # captured spritePack message (fixture-mode sprites)
docs/screenshots/panels/   # committed gallery: <type>-<size>.png, overwritten in place (D7)

Shim: settings/layout → defaults + localStorage; getBridgeStatus → connected; attach/interactive events fire once with interactive: true so the canvas mounts; updater/reportBug/relaunch → no-ops. Installed by main.tsx only when window.overlay is undefined and VITE_HARNESS is set — production builds are behaviorally untouched.

Data mode 1 — live-fake

Page-side WebSocket to 127.0.0.1:47474 against gradle runBridge -Pargs="--fake". Parses hello, {"batch":[...]}, and spritePack (~50 lines mirroring bridgeClient.ts). Real Java, real FakePacketSource, zero Electron.

Data mode 2 — fixture

?fixture=<name> loads a capture or hand-written scenario. Playback rebases timestamps (last batch ≈ now) so rolling windows render sensibly. Sprites from the committed spritePack.json. Deterministic → comparable shots.

Mount modes: full panel canvas (default), or ?panel=<type>&size=<sm|md|lg> mounting a single panel from registry.ts — the unit for gallery shots. npm run shots iterates every registered panel × size against gallery.json into the committed gallery paths: fixed viewport, deviceScaleFactor: 1, animations disabled, one pinned Chromium (the agent's Linux sandbox is canonical; local shots are for viewing, not committing).

The three eyes

1
Build agent — must look before the PR agent

Routine prompt (BUILD & FIX): if the change affects anything visible, run npm run shots, Read the changed PNGs and look, iterate until they match the acceptance criteria, commit them, embed the changed images in the PR body (raw URLs pinned to the head SHA).

2
Review agent — automated design review automated

review.yml prompt addition (parity-guarded → bridge first): if the diff touches overlay/src/renderer/ or the gallery, Read the committed screenshots and evaluate against the issue's visual acceptance criteria. A clear visual defect — placeholder text, clipping, unreadable contrast — is a finding like any other. The judge already has Read and is multimodal; no new tooling.

3
Maintainer — swipe the soak gallery, then decide to install human

release.yml's soak-issue builder diffs docs/screenshots/panels/ over origin/bridge..HEAD and embeds a SHA-pinned before/after pair per changed panel. Visually broken ⇒ soak:fail + comment without installing. Looks right ⇒ install and behavior-test.

Opt-in blocking signoff — ui:signoff

Maintainer labels the issue ui:signoff; a tiny pull_request_target label-sync job (no checkout) copies it to the PR via its Closes #N. Gatekeeper and sweep both hold a ui:signoff PR without ui:approved — one more hold beside soak-freeze / session-done / triage. Release: apply ui:approved. Reject with steer: comment + agent:retry (existing resume machinery). No auto-release backstop — unlike triage, this is a deliberate human gate; a held PR waits.

05

Feature 2 — Overlay test suite & capture replay

DpsTracker.ingest(packets) and LootTracker.ingest(packets) consume exactly the array shape a bug capture's recentPackets holds. Replay is nearly literal — written against soak #144's capture, this test fails on every build since PR #106:

const capture = loadCapture('soak-144-loot-empty')   // handles .json and .json.gz
const tracker = new LootTracker()
replay(tracker, capture)                                // fake-timer-anchored ingest
expect(tracker.entries.map(e => e.itemName)).toContain('<the white-bag item>')

Components

  • vitest + "test": "vitest run" in overlay/package.json, config reusing tsconfig.web paths.
  • test/replay.ts — loadCapture() + replay(): vi.useFakeTimers(), vi.setSystemTime(firstEnvelope.time), advance the fake clock to each envelope's time before ingesting (D3). Helpers to snapshot mid-replay for transient-state assertions.
  • Allowlist tripwire — every stream consumer exports CONSUMED_ENVELOPE_TYPES; a test asserts CONSUMED ⊆ CAPTURE_ALLOWED_TYPES (the set moves to src/shared/capture.ts so main + tests import one definition). Forgetting to extend the allowlist becomes a red test instead of a silently useless capture — the #144/#146 class.
  • Capture buffer upgrade (overlay/src/main/index.ts): 300 → 10,000 envelopes with per-type quotas (initial: MovePacket 500, NewTickPacket 1,000, ack types 300 each; measure a real session and tune) · compact JSON · gzip → realmshark-bug-<ts>.json.gz (est. 3–10 MB, under the 25 MB limit). Allowlist posture unchanged: default-deny, no chat/auth/credential types.
Regression-test contract (routine prompt, FIX / soak-fail modes)

If the work item includes a repro capture: download it, commit it under overlay/test/fixtures/captures/<slug>.json.gz, write a failing test that replays it and asserts the reported expected behavior, then fix until green. Fixture and test ship in the same PR as the fix.

Phase 2 — the Java mirror

src/test/java/bridge/replay/CaptureReplay.java: Gson-parse capture envelopes; map type (packet class simple name — the same strings the TS switch uses) → class via PacketType; gson.fromJson(env.data, clazz) (viable because PacketSerializer reflects field names verbatim; enums serialize as name strings; the raw byte[] is excluded and unneeded); feed DpsEngine exactly as DpsBroadcaster does; assert on the emitted snapshot. Covers the attribution class (#50, #98) and replaces hand-transcribing captures into Java by eye. Out of scope: RC4/reassembly — replay starts from decoded packets.

CI: ci.yml's overlay job adds npm test (human/local change); the Java mirror rides the existing gradle test step.

06

Feature 3 — Ground-truth corpus & asset facts

Capture-now & session recorder

Capture-now: the reportBug code path minus the issue form (parameterized IPC, not duplicated) — dump the ring to .json.gz, reveal in folder; exposed in tray + Status panel. Session recorder: a settings toggle appending every allowlisted batch as NDJSON to rolling .ndjson.gz files under userData/captures/ (~50 MB rotation). Recording becomes an afterthought, and it rescues the "bug happened before I pressed capture" case — the ring buffer's eternal weakness.

The corpus — overlay/test/fixtures/captures/

1
Per-issue attachments human attaches agent commits

The primary habit (feature form gains a Ground truth field: "does this touch game data the overlay hasn't parsed before? attach a capture / facts"). Every used capture is committed as a fixture by the agent's PR — the corpus grows itself.

2
Soak-fail attachments agent commits

Same contract via FIX mode (§05 callout).

3
One kitchen-sink seed session human records once

~20–30 min of varied play: dungeon boss phase change, realm event chain, white/orange bag drops, equip/unequip churn, players joining/leaving. Its role: the agent's standing documentation of wire reality ("what does a real UpdatePacket bag entity look like?") plus baseline coverage when an issue arrives with no fresh capture.

Privacy: allowlist filtering is automatic; the maintainer eyeballs files before they land in the public repo (player names are visible — maintainer's call).

Asset facts — assets/facts/asset-facts.json

IdToAsset/LootBagTypes/enchant parsing read the game's extracted XML from a real install at runtime — unobservable and untestable headless, which is precisely what produced the loot saga. AssetFactsExtractor (building on the existing resextractor machinery) runs on the maintainer's Windows PC and distills only the fields the code consumes:

{
  "gameBuild": "<exalt build id>", "extractedAt": "2026-07-14",
  "items":    { "9064": { "name": "Sword of Acclaim", "bagType": 6, "tier": 12,
                          "slotType": 1, "damage": [220, 275] } },   // loot classification (#144) + tooltips
  "entities": { "1292": { "id": "White Bag", "class": "<real class name>" },
                "1295": { "id": "Orange Bag", "class": "…" } },      // how bags REALLY self-describe — the Class=Bag assumption dies here, not in four soaks
  "enchants": { "17": { "name": "Sharpened III", "rarity": 2, "desc": "+12% damage" } },  // id → readable text (#113)
  "classes":  { "782": { "name": "Wizard", "slotTypes": [2, 9, 5, 6] } }
}

Consumers: (1) headless tests (LootBagTypesTest, IdToAssetBagIconTest, enchant parsing) run on real facts in CI; (2) registerFake is seeded from the facts file → FakePacketSource traffic uses real object types → --fake converges toward live behavior for free; (3) optionally the --fake bridge loads facts at runtime for realistic dev data without a game install. Lifecycle: rerun per game update; gameBuild makes staleness detectable; growing it is part of "new data area" feature prep.

08

Phasing — one agent issue at a time

Sequential, one agent:build label at a time — these PRs overlap on package.json/main.tsx/docs, and parallel agent PRs would churn the rebase loop. Soak cost of each wave is near zero (shipped-behavior deltas are a dev-flag guard, a button, buffer sizing), and phases 2+ progressively make their own verdicts cheaper.

A
Test suite + replay + capture upgrade agent

vitest · replay.ts · fixtures committed from the existing public soak captures (#144, #122, #50 — URLs go in the issue) · one regression test per fixture · allowlist tripwire · ring 10k/quotas/compact/gzip · docs. Human follow-ups: ci.yml npm test; routine-prompt self-check + capture→fixture contract.

B
Harness + shots agent

Shim, both data sources, ?panel/?size, Playwright, npm run shots, gallery + spritePack fixtures, initial committed gallery, docs. Human follow-ups: routine-prompt shots step; review.yml screenshot check; Playwright domain; then release.yml soak gallery + ui:signoff holds.

C
Capture-now + session recorder agent

Human: record the kitchen-sink session; commit baseline-session (small follow-up issue or local session).

D
Asset facts agent gated on human

Extractor + schema + facts-seeded registerFake + facts tests. Hard gate: real XML fragments for every parsed element attached to the issue (maintainer runs resextractor once) — otherwise this issue re-runs the loot saga. Human: run extractor, commit asset-facts.json.

E
Java CaptureReplay agent

Replay-based attribution tests over the by-then-existing corpus.

Risks & mitigations

RiskMitigation
Playwright download blocked in the routine sandboxRoutine env domain (human); fallback to preinstalled Chromium; failure reported under PR "Assumptions," never silent
Screenshot nondeterminism → noisy before/aftersOne pinned sandbox environment produces all committed shots; animations disabled; fixed viewport/DPR; humans + multimodal reviewer judge images — no byte-diff gating (non-goal)
Capture privacy on a public repoDefault-deny allowlist (unchanged) + maintainer eyeball before fixtures land; recorder writes allowlisted types only
Repo size growth (fixtures, PNGs)Gz fixtures (MBs); gallery overwritten in place (D7); Git LFS as a later escape hatch
Asset-facts licensingFacts-only interop data (ids/names/numeric fields), minimal, no asset binaries
ui:signoff PR waits forever if the maintainer forgetsAcceptable by design — a deliberate human gate (same posture as agent:needs-human); the label is opt-in per issue
Fake-timer replay diverges from live timing subtletiesAnchor to envelope.time (the same clock live code keys damage on); the Java mirror cross-checks attribution independently
Harness code shipping to usersVITE_HARNESS flag + tree-shaking + a build-time assertion that production bundles contain no harness module

Open questions

  1. Quota numbers (§05) are initial guesses — validate against a real session's type histogram before locking.
  2. Soak-gallery scope: changed panels only, or a full sweep including unchanged panels? Start changed-only; revisit if unchanged-panel regressions slip through.
  3. Corpus size vs CI time: if replaying 10k envelopes per run gets slow, split into per-scenario slices; reserve the full session for targeted tests.
  4. JDK in the routine sandbox (needed for live-fake mode's bridge jar)? Fixture mode carries the harness regardless; confirm on Issue B's first run.
